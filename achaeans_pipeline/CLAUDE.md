## Architecture

```
                    [ this CLAUDE.md — orchestrator ]
                                  │
             ┌────────────────────┴────────────────────┐
             ▼                                         ▼
  [ Internet Archive API ]                [ Wikimedia Commons API ]
   the-trojan-horse-1961                   3 pottery/artifact files
   helena-1924                             4 Baroque/Neoclassical oils
             │                                         │
   (manifest scan → companion images         (Action-API title resolution
    + smallest MP4 derivative only)           → polite file-by-file pull)
             │                                         │
             └────────────────────┬────────────────────┘
                                  ▼
                   [ achaeans_curated_library/ ]
                     ├── *.jpg            ← 7 Commons artworks
                     ├── <archive-id>/    ← IA stills + small MP4s
                     └── clips/           ← ffmpeg-cut short clips
```

Everything lives in `pipeline.py`. Phases run independently:

```sh
pip install -r requirements.txt     # requests + internetarchive
python pipeline.py verify           # Phase 0: resolve manifest titles, NO downloads
python pipeline.py seed-ledger      # Phase 0b: glossary identities → ledger gate
python pipeline.py art              # Phase A: Commons artworks
python pipeline.py films            # Phase B: IA stills + small MP4s
python pipeline.py clips            # Phase C: local ffmpeg cuts (needs timestamps)
python pipeline.py                  # = all (clips no-op until timestamps set)
python pipeline.py discover "mycenaean phalanx"      # Phase D: one term
python pipeline.py discover --terms-file terms.txt   # Phase D: bulk hunt
```

## Run protocol

0. **Phase 0 (verify) — run this first.** Seven polite API pings, zero
   downloads. Prints `exists [license]` or `MISSING` per manifest title. For
   each MISSING title: `discover` the subject, pick the right candidate from
   the manifest it writes, paste that exact `File:` title into
   `WIKIMEDIA_ASSETS`, re-verify.
1. **Phase A (art).** Each Commons title is resolved via the MediaWiki Action
   API before download. A title logged `MISSING on Commons` means the brief's
   spelling was wrong — find the real page via commons.wikimedia.org search,
   fix `WIKIMEDIA_ASSETS`, re-run (existing files are skipped). Licenses print
   per file; accept PD / CC0 / CC-BY / CC-BY-SA only, same standard as the
   glossary.
2. **Phase B (films).** The item **manifest is scanned first** and only
   preferred formats are pulled (companion JPEGs/PNGs + the small MP4
   derivative, e.g. `512Kb MPEG4`) — never the multi-GB master. If neither
   item exposes a preferred format, the script prints what the manifest does
   have; extend `IA_VIDEO_FORMATS` with the smallest real one.
3. **Phase C (clips).** The two `CLIP_SPECS` starts ship as `None` on purpose.
   Eyeball the downloaded MP4s (scrub in QuickTime or `ffplay`), find:
   * `the-trojan-horse-1961` (Ferroni 1961): the bronze-armoured **phalanx
     forming up** — cut 6 s;
   * `helena-1924` (Noa 1924, silent): the full-scale **naval landing of the
     Achaean fleet** — cut 10 s;
   then fill in the `start` timestamps and run `python pipeline.py clips`.
   Cuts re-encode (libx264, crf 20) for frame accuracy. `ffmpeg` must be on
   PATH (`brew install ffmpeg`); no moviepy.
4. **Phase D (discover) — the bulk hunt.** The user has **500+ terms** to
   source, and the scope is **Odyssey — do not deviate yet** (user decision
   2026-08-14). Write the user's Odyssey terms to `terms.txt` when they
   supply them (one per line, `#` comments allowed — appending context words
   like "history art painting" per line is fine and often sharpens results).
   A 191-term historical-Greece list mined from Cartledge sits **parked** in
   `terms-cartledge-parked.txt` for a possible later expansion — do not feed
   it to discover without the user's say-so. Then
   `python pipeline.py discover --terms-file terms.txt`. Per term it makes
   **one** search call and writes
   `achaeans_curated_library/discovery/<slug>.json` — candidates already
   filtered to PD/CC0/CC-BY/CC-BY-SA (NC/ND rejected server-side of this
   script), sorted by resolution, each with `title`, `license`, dimensions,
   direct `url`, and `source_page`. **No images are downloaded** — review the
   manifests, promote winners into `WIKIMEDIA_ASSETS` (or a follow-up bulk
   ingester), then run `art`. Discovery is resumable: a term whose manifest
   file already exists is skipped, so an interrupted 500-term run re-runs
   from where it stopped with zero repeat requests. Budget ~2.5 s/term:
   500 terms ≈ 21 minutes of polite pinging.

   *Why Commons search instead of Google Custom Search:* Google's
   `rights=cc_publicdomain` filter trusts self-reported page markup and
   returns bare hotlink URLs with no license record; Commons returns
   structured, community-verified license metadata, needs no API key, and is
   where the well-digitized PD classical material lives. (A Google-CSE
   leads-generator was considered and declined 2026-08-14.)

## Sourcing brief — kinds of works (PARKED context, not current scope)
**Current scope is Odyssey-only** (user decision 2026-08-14): mythic
subjects, illustrated the way the live glossary already does it — fine-art
paintings, vases, sculpture of Homeric scenes. The brief below was derived
from Cartledge (*Ancient Greece: A VSI — A History in Eleven Cities*:
Cnossos, Mycenae, Argos, Miletus, Massalia, Sparta, Athens, Syracuse,
Thebes, Alexandria, Byzantion, plus Olympia & Delphi) and applies to a
possible LATER historical-Greece expansion — keep it, don't act on it yet.

**The canonical illustrations for historical Greece are NOT paintings.** Of
Cartledge's 24 plates, zero are fine art in the Odyssey-glossary sense. They
are: **site photographs** (aerial Cnossos, Lion Gate, Erechtheum Caryatids,
Apollo's temple at Delphi), **excavated artifacts** (Vapheio gold cups, Mask
of 'Agamemnon', Argos panoply, Vix krater, Arcesilas cup, ostraca, Miltiades'
helmet), **coins** (Athenian owl tetradrachm, Syracuse decadrachm),
**sculpture** (Doryphoros, Nike of Paeonius, Delphi Charioteer, Azara Herm,
Lion of Chaeronea), one **mosaic** (Alexander at Issus), plus maps and site
plans. Mythic subjects (the existing glossary's territory) keep their
paintings; historical terms want the archaeology.

**Term families to expect in the 500+ hunt** (mirroring the book's Glossary /
Who's Who / cities): (1) *institutions & concepts* — acropolis, agora, agôgê,
ostracism, hoplite, trireme, democracy, coinage; (2) *people* — historical
(Pericles, Aeschylus, Alcibiades, Alexander) and mythic (Agamemnon, Apollo);
(3) *places* — cities, sanctuaries, battlefields. Cartledge models how to
illustrate a concept: **ostracism → a photo of actual ostraca; coinage → a
tetradrachm**. The Wikipedia-article harvest excels exactly here — the
article on "Ostracism" already carries curated ostraca images.

**Consequences for this pipeline:**
* Photos of 3-D objects carry the *photographer's* copyright (no PD-Art
  rule, unlike faithful 2-D painting scans) — the license filter matters
  more here; CC-BY/CC-BY-SA museum photos are the norm and are fine.
* Famous artifacts have MANY Commons photos from different angles —
  perceptual hashing will NOT see two angles of the Mask of Agamemnon as
  duplicates. Identity is object-level: pick ONE photo per object
  deliberately, and prefer the Wikidata-depicts (P180 = the specific
  object's QID) layer for identification.
* The book's own plates are rights-managed (Getty/akg/Bridgeman) — never
  source from the EPUB's images; every one of those objects exists freely
  on Commons.

## Identification method — why keyword `discover` alone isn't the ceiling
(2026-08-14 discussion, not yet built.) For 500+ mostly-entity terms
(heroes, gods, places), keyword search is the weakest layer. Ranked best to
fallback:
1. **Commons "depicts" search** (`haswbstatement:P180=<QID>`) — files a
   human tagged as depicting THIS entity, not just files whose description
   contains the word. Resolve term → Wikidata QID first (one call); this
   also disambiguates for free (Ajax the hero vs. the football club).
2. **Wikipedia-article harvest** (`generator=images` on the term's article)
   — the method that built most of the LIVE glossary's 492 artworks
   already (see repo-root CLAUDE.md); Wikidata P18 gives the community's
   single canonical image per entity.
3. **Commons categories** (`Category:Achilles in art`) — good recall once
   the right category is found.
4. **Keyword search** (what `discover` does today) — fallback only, for
   non-entity terms (abstract concepts, scene descriptions).
Explicitly rejected: **Google Arts & Culture** — no public API, ToS forbids
scraping, full-res withheld by design; it's a browse-to-learn-the-name UI,
not a source. **Museum open-access APIs** (Met CC0, AIC, Rijksmuseum,
Cleveland, Smithsonian) are a worthwhile ENRICHMENT layer over
Wikidata/Commons — authoritative attribution, pristine masters — but too
patchy per-subject to be the primary finder.
If/when built, this becomes a `discover` upgrade: resolve QID → P18 + P180
search → category → keyword fallback, same manifest/polite/resumable shape.

## Choosing the best copy — clarity, colour balance, resolution
Commons usually holds several copies of a famous work (museum scan, book
plate, visitor photo, upscale). Selection is three layers, cheap → decisive:

1. **Metadata priors (free, at discover time).** Manifests capture Commons'
   community grading (`assessments`: featured/quality/valued) and `select`
   flags colour-managed sources by title ("Google Art Project", Rijksmuseum,
   Met, Cleveland — museum-run digitizations with trustworthy colour). A
   featured Google-Art-Project scan almost always wins outright.
2. **Measured proxies: `python pipeline.py select "<term>"`.** Pulls 512px
   renditions of the manifest's top candidates (~6 polite requests), scores
   each — *sharpness* (edge-filter variance; blur and upscales score low),
   *clipping* (blown highlights / crushed shadows), *colour cast* (R/G/B
   spread — yellowed book plates stand out, but ONLY compare siblings of the
   same work: genuinely warm artworks are warm in every faithful copy),
   *bytes-per-pixel* of the original (over-compressed files and upscales
   score low), plus megapixels — into `discovery/select/<slug>_scores.json`.
3. **Eyes decide.** The same command writes
   `discovery/select/<slug>_montage.jpg` — all candidates side by side,
   index-labelled. View it (the session running this has vision), pick, and
   put the winner's title into `WIKIMEDIA_ASSETS`. Scores rank; they don't
   choose. This is the same montage-confirmation discipline the glossary's
   perceptual dedup used.

**Resolution policy:** originals wider than `MAX_LONG_EDGE` (3200px) are
downloaded as Commons-rendered derivatives at that width — plenty for
lightbox zoom, and it spares both our disk and Commons' bandwidth from
100-megapixel museum TIFFs. The ledger records the ORIGINAL's sha1/pageid
either way, so identity gating is unaffected. Beware the inverse trap too:
a 600px-wide "original" is below card-cover quality — prefer ≥1600px on the
long edge; `select`'s megapixel column makes the small ones obvious.

## No-duplicates assurance (mandatory)

The glossary's original harvest hit ~90% dedup success with a post-hoc
perceptual sweep alone. This pipeline layers **prevention (arrival-time
gates)** over **detection (the `dedupe` audit)** so duplicates mostly never
land, and the sweep only mops up what identity checks cannot see.

**Seed first: `python pipeline.py seed-ledger`** (run once, before the first
`art` run). It resolves every art.json `source` title against Commons and
writes each live artwork's `sha1` + `pageid` into `library_ledger.json`
(entries marked `"origin": "glossary"`). Without seeding, the app's artworks
are only protected by title matching (gate 1); with it, gate 3 also refuses
the *same artwork* arriving under a renamed page or re-uploaded copy. ~582
titles batched 50 per request ≈ 12 polite API calls via POST (titles overflow
GET URLs), following redirects so renamed files still seed. Idempotent —
re-runs skip already-seeded titles. Sources reported "gone from Commons"
remain covered by the title gate.

**Prevention — gates inside the `art` download loop, in firing order:**
1. *Glossary gate (pre-network):* the title, normalized, already appears as a
   `source` in `../src/data/art.json` → REFUSED. (Real example: Gemini's
   manifest wanted the Exekias Achilles-and-Ajax amphora, which is already
   live as `achaeans-1` under a different Commons filename.)
2. *Ledger title gate (pre-network):* `library_ledger.json` (written on every
   successful download, consulted before any) already holds that title →
   REFUSED.
3. *Identity gate (post-resolve, pre-download):* the resolved file's Commons
   `sha1` or `pageid` matches a ledger entry → REFUSED — catches the same
   bytes re-uploaded under a different name, and renamed pages, before any
   image bytes move.

Discovery manifests capture `sha1` + `pageid` per candidate for the same
reason: when promoting candidates into `WIKIMEDIA_ASSETS`, assign each file
to exactly ONE term (the `dedupe` audit's layer 1 reports cross-term
claims). Never edit `library_ledger.json` by hand except to remove an entry
whose file you deliberately deleted.

**Detection — `python pipeline.py dedupe` after every harvest batch:**
1. *Identity collisions* across all discovery manifests (same pageid/sha1
   claimed by >1 term).
2. *Cross-library:* candidates or downloads whose title is already an
   art.json source. A **downloaded** glossary match is a hard failure
   (exit ≠ 0), same loud-guard philosophy as `scripts/check-pins.ts`.
3. *Perceptual:* dHash+aHash sweep over everything downloaded, and against
   the local `../public/art/*.jpg` masters (excluding `map-*`) when present —
   catches same-artwork-different-file (crops, rescans, caption-baked
   copies). Thresholds are the tellmeohmuse-proven **dHash≤12 AND aHash≤18**.
   Pairs are *candidates*: confirm visually (view both files side by side —
   dark images throw false positives) before deleting the lower-res copy.
   Exact byte-dupes (local sha1) are hard failures.

Report lands at `achaeans_curated_library/dedupe_report.json`.

The residual risk past all layers is the same one the glossary had: the same
*artwork* photographed by two different institutions. The perceptual sweep
catches most; the layered-discovery upgrade (Wikidata P6243 "digital
representation of" — two files pointing at the same painting QID are the same
artwork regardless of pixels) is the designed fix if that residue matters.

## Politeness standard (mandatory — do not loosen)

* 2.5 s `time.sleep()` between **every** remote request, API metadata pings
  included. Don't parallelize the loops; don't shrink the delay.
* Every download is skip-if-exists (`ignore_existing=True` on IA; an existence
  check + atomic `.part` rename on Commons), so interrupted re-runs make zero
  duplicate connections.
* Every Commons request carries the descriptive `USER_AGENT` with a real
  contact address, per Wikimedia's User-Agent policy.
