## Journey of Odysseus map (`src/JourneyMap.tsx`)
- Leaflet **CRS.Simple** image map over the *Vlyssis Errores* base — served as-is from R2 at `art/map-wanderings.jpg` (same object as the glossary's wandering-isle place entries; native 4000×2337, no resize needed since R2 has no on-the-fly transform, see "Image hosting" below). Coordinate space = the master's pixel size; `const W=4000, H=2337`. `yx(x,y)=[H-y,x]` flips y for CRS.Simple. **Note:** the old Cloudinary setup version-pinned this URL (`/v<ver>/<public_id>`) specifically to bust browser cache on re-upload; that mechanism doesn't exist for a flat R2 key — if this master ever needs replacing in place, add a cache-busting query param or use a new key, don't just overwrite silently (same caveat as the general R2 "swap an image" note below).
- **15 voyage stops** (`STOPS`, 14 canonical per Stephen Fry's "Journey of Odysseus" plus one extra) hand-calibrated onto Ortelius's own labels (Troy/Ilium, Cicones/Ismarus, Aeaea/Circe, Cimmerii/Hades, etc.). Each links to its glossary `term`. The extra stop is Odysseus's second landing on Aeaea (Book 12: he actually beaches the ship and stays the night to bury Elpenor and get Circe's final sailing directions, not just sail past) — it reuses `term: "Circe"` (same island, same glossary entry/artworks) so it needed its own React `key` (`s.n`, not `s.term`, since two stops now share a term).
- **Narrative sea route** in `LEG_VIAS[i]` (per-leg bend points) — faithful to Homer: round Cape Malea to the Lotus-Eaters, the western-Ocean dip to Hades and **back to Aeaea** (Circe visited twice), the **Scylla/Charybdis strait threaded twice** (out + the wreck-driven double-back). Smoothed with **centripetal Catmull-Rom** (`smooth()` — centripetal, not uniform, to avoid overshoot on uneven spacing; emits `ROUTE_SEG` points per control-segment, so input point `k` lands at smoothed index `k*ROUTE_SEG`). Drawn as two polylines: a white **casing** under the purple. **Gotcha:** the casing must use the **same `journey-route` dash+animation** as the purple — a *solid* casing fills the dash gaps and kills the marching-ants effect.
- Features: guided **tour**, zoom-aware place-name labels, hover tooltips, **click-popup** with bilingual entry info + "View artworks" (`lookup` prop from App resolves term→entry; the map stays open under the lightbox so closing returns to it), an overview **navigator** (`leaflet-minimap`), and a Fry-style legend.
- **Tour camera** (`TourController` + `panAlong`): between *adjacent* stops the camera **glides ALONG the route curve at a fixed `TOUR_ZOOM`** (rAF tween over the curve slice `routeLatLng[stopRouteIdx[from]..stopRouteIdx[to]]`, speed scaled to leg pixel-length, clamped) — NOT `flyTo` (which zooms out-then-in and feels disconnected). Non-adjacent jumps and the first stop ease straight in; idle (`idx<0`) zooms out to the whole map. Glide pace is by **on-screen pixels** (`glideMs(px)` = `TOUR_PPS` 150 px/s, clamped `GLIDE_MIN`/`GLIDE_MAX` 3.5–11s) — a sail, not a whip. **Cadence is decoupled, not a fixed `STOP_MS`:** each stop holds for `cycleMs = glide-in + DWELL_MS` (3.5s), so the huge Cicones→Lotus-Eaters leg (~6800px screen, vs ~700px typical) can glide its full ~11s without starving the dwell on short stops. `legGlideMs(from,to)` measures the route slice the same way `panAlong` does (px·2^TOUR_ZOOM), so timer + camera agree; both the auto-advance `setTimeout` and the **countdown bar** (`tour-progress` keyframe, `key`'d per stop) use `cycleMs`. A tiny antique-galley **ship** (`shipIcon` divIcon) rides the route during the tour — `panAlong`'s `onMove` callback `setLatLng`s it each frame; since the camera centers on that same point it sits at screen-center while the map scrolls (hidden via `opacity:0` when idle). Legend clicks drive a separate `focus` state that pans the camera through the same `TourController` while **keeping the legend open** — they don't start the tour or open artwork.
- **URL route:** `#journey` opens the map (App reads `window.location.hash`); `#journey/edit` (legacy alias: `#humaneyeball`) opens it in **calibration mode** — drag pins, click the route to add a sea-bend, drag/dbl-click bends, then "Copy coordinates" to get the `{stops, legVias}` JSON to paste back into the source.
- **Stop deep links (`#journey/<slug>/@<term>`)** — the Atlas's `#atlas/…/@<term>` twin, same `splitFocus` parser in `App.tsx`. `findStop(term, preferSlug?)` in `src/data/journeys/index.ts` matches exact term → **place alias** → case-insensitive, and the route always carries the STOP's canonical term. The alias table is `src/data/journeys/aliases.ts` (`JOURNEY_ALIASES[slug]`), because Wilson's glossary indexes the *place* while a stop is keyed by the entry its popup opens — usually the being who lives there: Aeaea→Circe, Aeolia→Aeolus, Ismarus→Cicones, Land of the Cyclopes→"Cyclops (pl. Cyclopes)", Land of the Lotus-Eaters→Lotus-Eaters, Telepylus→Laestrygonians, The Underworld→Hades. It lives in **its own file, not on `JourneyConfig`**, so `scripts/check-pins.ts` can import it (the journey configs import `.svg` assets, which tsx can't load — the same constraint that forces that script to regex their stop terms); `check:pins` validates every alias against the journey, the glossary and that journey's stops. The five Underworld rivers are deliberately NOT aliased — each has its own distinct rubri pin, and folding them onto stop 8 would throw that away. `JourneyMap`'s `focusTerm` prop drives the legend's own `focus` state (so `TourController` does the flying and the legend highlights the stop) and a `FocusPopup` opens that stop's popup on `moveend`, keyed by the stop's stable `n` (term-keyed would collide — Aeaea is two stops). It goes null on tour start or another legend click, which closes the popup.
- **Which map a term opens is decided in ONE place: `src/data/mapRoutes.ts`** (`mapRoute` / `mapLinks`). Both the place cards and the Atlas's own header search resolve through it, so a term can't route two ways depending on where you clicked. Rule: the Journey map wins when `findStop` hits **and** the context-free `findPin` says the term's owning plate is `rubri` — rubri's Greek content *is* the Vlyssis inset the Journey map shows at full size, so the Atlas could only offer a worse copy of the same engraving. That resolves to 9 places (Aeaea, Aeolia, Land of the Cyclopes, Land of the Lotus-Eaters, Ogygia, Scheria, Telepylus, The Underworld, Thrinacia). Troy/Ithaca/Ismarus sit on Graecia and keep it as their primary. **Card affordances:** whole-card click goes to the primary map (map-only places) or the gallery; a small **"Voyage"** button (Sailboat icon) shows whenever the voyage is an *additional* destination — Troy and Ithaca carry Map + Voyage — and character stops (Circe, Scylla, the Sirens…) get one too. Both live in the shared `MapLink` component in `App.tsx`, which `stopPropagation()`s so the card's own click doesn't also fire.
- **Hero mini-map:** the hero carries a clickable crop of the voyage map (`public/journey-map.jpg`, cut from `public/art/map-wanderings.jpg` around the 15 stops — it happens to frame the "VLYSSIS ERRORES" cartouche) that opens `#journey`. Committed to the repo like `hero.jpg`, but **lazy and NOT preloaded**: `hero.jpg` is the LCP element and this must not compete with it.
- **Gotcha — `map.setMinZoom(z)` BEFORE the opening `setView` strands an animation that lands late and clobbers the camera.** When the map's current zoom is below the new floor, Leaflet's `setMinZoom` fires its own **animated** `setZoom` (target: bounds centre at min zoom), and an `animate: false` `setView` afterwards does *not* clear that animation's pending `transitionend` — the stale handler runs `_move(_animateToCenter, _animateToZoom)` seconds later and snaps the view back to "fit all". It had been silently undoing this map's documented "open on the first stop" behaviour forever, and it ate every deep-link `flyTo` on cold load. **Fix in `LockMinZoom`: set the view first, raise minZoom second** (then the floor is one the map already sits on, so there's nothing to strand); also return early while the container is still 0×0 rather than computing `getBoundsZoom` on it. `LockMinZoom` announces readiness via an `onReady` prop (pass a **stable** fn — a `useState` setter — it sits in the effect's deps) only once the opening view has landed *and* the 300ms settle pass has run, which is what `focusTerm` gates on; announcing earlier let the settle's `getZoom() < z` clamp fire mid-flight (flyTo's parabolic path dips below its start zoom). **Debugging note:** `map.getZoom()` reports the *old* zoom while the pane is visibly scaled mid-animation, and background-tab throttling stretched a 0.9s flyTo to ~6s — measure `.leaflet-image-layer`'s width (`4000 × 2^zoom`) instead of trusting the API or a screenshot, and force a paint between steps.
- **Mobile:** modal goes full-screen, the wide map **covers** the screen (min zoom = `getBoundsZoom(bounds, true)`) and pans horizontally (follows the east→west voyage); opens focused on Troy; legend hidden, tour controls live in the tour card.
- **Calibration workflow:** to reposition pins/route, open `#journey/edit`, drag, copy the JSON, and bake values into `STOPS` / `LEG_VIAS` (don't hand-guess coordinates). To locate a label on the map, crop the master with PIL + a coordinate grid and view it. The floating "Calibration" panel (live JSON dump + Copy button) is the shared `src/CalibrationPanel.tsx` — see its own section below.
- **react-leaflet `pathOptions.className` is dropped in the PRODUCTION build (works in dev) — a real trap.** `createPathComponent` calls `new L.Polyline(positions, options)` with `className` nested inside `pathOptions`, but Leaflet only reads a *top-level* `options.className` in `_initPath`, and react-leaflet applies pathOptions via `setStyle()` which **never touches className**. So the class is never put on the SVG path. It *appears* to work in `vite` dev ONLY because StrictMode's double-mount re-runs `_initPath` after `setStyle` happened to merge className into the options — a fluke absent from the single-mount prod bundle. Symptom this session: the `journey-route` marching-ants class (hence the animation) vanished in production while fine on localhost. **Fix: apply the class yourself on the layer `add` event** (`eventHandlers={{ add: e => e.target.getElement()?.classList.add("journey-route") }}` → `markRoute`), not via `pathOptions.className`.
- **Dev/testing gotchas:** ports **5173/5174 are usually taken** by sibling projects (e.g. *Chord Drill*) — the dev server lands on a higher port; check the Vite log for the real one. **Dev≠prod for the map:** Vite serves CSS unminified and React in StrictMode, so the className bug above and any minifier CSS rewrite hide in dev — reproduce production issues with `npm run build` + `vite preview`. The `chrome-devtools` MCP refuses to attach if a Chrome with its profile is already open; fall back to driving the live/preview URL with **Playwright WebKit** (Safari engine — the iPhone test target) via the npx-cached `playwright` (scripts must live in that dir to resolve the module). When testing the **tour/animated state**, same-URL `#journey` navigation does **not** reset React state, and multiple open tabs each run their own timers — both cause misleading "advancing too fast" readings. Force a fresh mount (navigate to `/` then `#journey`, or a new tab) and verify intervals with `console.log(performance.now())`. Cadence is **per-leg `cycleMs`** (glide-in + `DWELL_MS`), not a single fixed value.
