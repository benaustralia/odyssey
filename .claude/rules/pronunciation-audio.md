## Pronunciation audio (ElevenLabs) — `src/PronounceButton.tsx`
A small speaker button next to `{e.pron}` on both the home-page cards (`App.tsx`) and the prerendered entry page (`EntryContent.tsx`) — one shared component so the two render paths can't drift, same reasoning as the maps' shared `CalibrationPanel`. Clicking plays a slow syllable-paced clip, then (on `ended`) a natural-speed clip — two plain `Audio()` instances, no library, `stopPropagation`'d since the button sits inside the card's own clickable area.
- **Pipeline is ONE ElevenLabs call per entry, not two.** The first design generated both clips from the API: a natural read, and a "slow syllable walk" built by joining the curated `pron` respelling with ellipsis pauses (e.g. `/uh-KEE-unz/` → `"uh… KEE… unz"`) at `speed≈0.7`. **Confirmed by ear this fails** — the model doesn't know what to do with a jammed phonetic pseudo-word, while the same term read as real text ("Achaeans") comes out perfect. Fixed by dropping the ellipsis-text call entirely: `scripts/tts-pronunciation.ts` requests only the real term text at natural speed, then derives the slow clip **locally** with `ffmpeg -filter:a atempo=0.6` (pitch-preserving tempo stretch, not a pitch-shifted "chipmunk" effect) — half the API cost as a side effect of being the better-sounding design, not the goal. 0.6× was chosen over 0.7× after an A/B that turned out inaudible on short words (~0.19s absolute difference on a 1s word) — go with the more pronounced option when a comparison is a wash.
- **Voice: Alice** (`Xb7hH8MSUJpSbSDYk0k2`), British, "Clear, Engaging Educator" — picked from the account's actual voice library (queried via `GET /v1/voices`, never guessed) over George/Daniel/Lily specifically for slow-speech articulation clarity. Model `eleven_multilingual_v2`. Explicitly NOT `sai9UY7iXkRDSsXHR0bZ`, the young-Australian voice the sibling `NAPLANSpelling` project's own TTS script uses.
- **Credentials live in `.env.elevenlabs.local`** (git-ignored via the repo's `*.local` rule) — `ELEVENLABS_API_KEY` / `ELEVENLABS_VOICE_ID` / `ELEVENLABS_MODEL_ID`. **Gotcha:** `NAPLANSpelling`'s own `.env.local` copy of this key is a 64-char *key ID*, not a usable `sk_...` secret — ElevenLabs' API rejects it outright ("API key ID used as API key"). `netlify env:get`/`env:list` against that project's linked Netlify site were also inconsistent (empty in the `dev` context, flaky in `production`). Simplest fix when this happens again: generate a fresh key straight from the ElevenLabs dashboard (Settings → API Keys) rather than trying to extract a sibling project's stored one.
- **Generation:** `tsx scripts/tts-pronunciation.ts [termOrSlug...]` (no args = every entry missing a clip; `FORCE=1` re-renders existing ones). Idempotent, same shape as `NAPLANSpelling`'s sibling script. Output goes to `public/audio/<slug>-{slow,fast}.mp3` (git-ignored, kept locally as the upload master — same pattern as `public/art/`).
- **Hosting:** R2, `audio/<slug>-slow.mp3` / `audio/<slug>-fast.mp3` — `scripts/upload_to_r2.py` walks `public/audio/*.mp3` alongside art masters and atlas tiles (one uploader, `ContentType` now picked per-extension rather than hardcoded to `image/jpeg`). `audioUrls(e)` in `src/lib/entries.ts` builds both URLs from `slugify(e.term)`, mirroring `assetUrl()`.
- **QA method:** before spending the full-batch API budget, render a few test entries and publish them as a **self-contained Claude Artifact** — base64-embed the mp3s directly in the HTML (CSP blocks external audio requests anyway) so it's a real URL a phone can open, rather than relying on file attachments. Used twice: once to catch the ellipsis-text failure, once to A/B the ffmpeg tempo factor.
