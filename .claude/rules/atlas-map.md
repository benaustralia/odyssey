## Atlas map (`src/AtlasMap.tsx`)
- **Config-driven, multi-plate** (mirrors `JourneyMap`'s `src/data/journeys/` pattern): `src/data/plates/{types,index,<slug>}.ts` is the registry — `types.ts` defines `AtlasPlace` (`term`/`label?`/`noGloss?`/`x`/`y`) and `PlateConfig` (`slug`/`title`/`w`/`h`/`maxZoom`/`tileBase`/`attribution`/`places`); `index.ts` exports `PLATES: Record<string, PlateConfig>` + `DEFAULT_PLATE_SLUG` (currently `"graecia"`). `AtlasMap.tsx` itself takes `config` + `editing` props (no module-level constants) and renders a `<select>` plate switcher in the modal header.
- **6 plates**, all Ortelius (Theatrum Orbis Terrarum): `rubri` (*Erythraei Sive Rubri Maris Periplus*, 1597 — the original full-Red-Sea plate: Egypt/Arabia/Persia/India/East Africa plus the cramped Aegean *Vlyssis Errores* inset that the Journey map also uses; 13238×10802px, maxZoom 6, ~3010 tiles), `graecia` (*Graecia Sophiani* — the primary Greek map, mainland Greece/Peloponnese/Crete/Aegean at real cartographic scale; 12325×8913, maxZoom 6, ~2334 tiles), `aegyptus` (*Aegyptus Antiqua*, 6498×9896, maxZoom 6, ~1373 tiles), `natoliae` (*Natoliae... Asia Minor*, 5560×7725, maxZoom 5, ~923 tiles), `palestinae` (*Palestinae sive... Terrae Promissionis*, 8000×6144, maxZoom 5, ~1025 tiles), `africae` (*Africae Tabula Nova*, 12504×9430, maxZoom 6, ~2470 tiles). Masters/tiles live in git-ignored `plates/<slug>/` (not `public/art/` — a separate directory since the artwork and Atlas upload passes were built independently, though both now go through `scripts/upload_to_r2.py`). **Gotcha:** `rubri`'s tile pyramid predates the `plates/<slug>/tiles/` convention and was never actually persisted locally — only `plates/rubri/master.jpg` survived. It had to be regenerated (`vips dzsave` as above) during the Cloudinary→R2 migration; if any other plate's `tiles/` dir is ever found missing, the fix is the same — the master is the durable source of truth, tiles are always reproducible from it.
- **Why tile pyramids, not `ImageOverlay`s like JourneyMap:** each master is 60–140MP, far past what any live crop/transform endpoint could crop in one request — doubly true now: R2 has **no on-the-fly transform API at all** (Cloudinary at least had `c_crop`; R2 serves flat objects only), so pre-slicing offline is the only option, not just the fastest one. Sliced via `vips dzsave <master> tiles --layout google --suffix '.jpg[Q=82]' --tile-size 256 --overlap 0` (via `scripts/make-plate.sh <slug> "<Commons file title>"`, which also curls the master from `https://commons.wikimedia.org/wiki/Special:FilePath/<title>`).
- **Hosting:** each tile uploaded to Cloudflare **R2** (bucket `odyssey-assets`, public `pub-b57180e24c9841f58854ecd1c164523a.r2.dev` domain) at a **deterministic** object key, uniform across all 6 plates: `atlas/<slug>/{z}/{row}/{col}.jpg` (`config.tileBase` picks the `atlas/<slug>` prefix; the pre-namespacing legacy bare-`atlas` exception rubri had on Cloudinary was NOT carried over — R2 is a fresh key space). Uploaded via `scripts/upload_to_r2.py` (boto3 against R2's S3-compatible endpoint — see "Image hosting" below for why, and for credentials). Deterministic keys mean tile URLs need **no lookup manifest**: `${R2}/atlas/<slug>/{z}/{y}/{x}.jpg` — note the literal `.jpg` suffix per object (unlike Cloudinary's content-negotiated delivery, R2 objects were uploaded with explicit extensions).
- **Minimap thumbnails have no live-transform equivalent either:** the old `thumbUrl()` did a Cloudinary `c_crop` to pull just the plate's real content bounds out of the z0 tile's white-padded 256×256 canvas (see the padding note below). R2 can't do that on request, so each plate's crop is pre-baked *once* at upload time into a dedicated `atlas/<slug>/thumb.jpg` object (crop math: `ceil(w/2^maxZoom)+2 × ceil(h/2^maxZoom)+2` from `(0,0)` on the local `tiles/0/0/0.jpg`, then upload). Re-run this by hand (a short PIL + boto3 script, not currently a checked-in tool) any time a plate's tiles are regenerated.
- **Gotcha — tile addressing is TRANSPOSED:** `vips dzsave`'s "google" layout writes tiles on disk as `{z}/{row}/{col}.jpg` — row is the directory, col is the filename — the transpose of Leaflet's `{z}/{x}/{y}` template (x=column, y=row). Get this backwards and the map renders as a **scrambled, transposed puzzle** (each tile intact, wrong tile in each cell) — NOT a blank/missing-tile failure, which makes it a confusing bug to spot. Fix: swap y/x in the URL template (`atlas/{z}/{y}/{x}`, not `atlas/{z}/{x}/{y}`).
- **Gotcha — `L.CRS.Simple.unproject(point, zoom)` called STATICALLY silently skips the scale division** (it just applies the axis-flip transform to whatever raw point you give it) — only the LIVE MAP INSTANCE's `map.unproject(point, zoom)` correctly divides by `scale(zoom)=2^zoom` first. Bounds/marker math built from the static call end up in raw pixel units, and `fitBounds` "solves" the resulting nonsense box by landing on a wrong zoom, which makes the tile grid compute negative row/col indices (a wall of 404s like `atlas/2/-2/1`). **Always compute bounds/positions via the live map's instance methods** (`unprojectPixel(map, x, y, maxZoom)` helper in `AtlasMap.tsx`), never the static `L.CRS.Simple` object.
- **Modal-mount timing:** react-leaflet's initial `bounds`-prop fit runs before the modal's CSS layout has settled (container still 0×0) — fixed with a `ResizeObserver` (`FitWhenReady`) that fits once the container has real dimensions. Must fit **only once** (guarded by a `fitted` flag) — re-running `fitBounds` on every observed resize (Leaflet's own zoom-animation causes micro-reflows the observer also sees) snapped the view back to "fit all" on every scroll-zoom tick, making scroll-to-zoom appear completely broken. Same one-shot idea as `JourneyMap`'s `LockMinZoom` (`focused` flag). Switching plates remounts `AtlasMap` via `key={slug}` so this and tile-prefetch state reset cleanly.
- **Mobile "cover" fit:** same fix as `JourneyMap`'s `LockMinZoom` — `map.getBoundsZoom(bounds, true)` as the min zoom, so the map always fills the frame instead of "fit inside" leaving grey letterbox bands on a portrait phone (caught only by testing on an actual iPhone SE simulator, not visible on desktop where the container is aspect-locked to the image via `sm:aspect-[...]`).
- **Calibration:** `#atlas/edit` (default plate) or `#atlas/<slug>/edit` (any plate) — Shift+click the map to drop a new pin (named "untitled", rename in the footer panel), **drag existing pins** to adjust (`dragend` converts the marker's `getLatLng()` back to pixel coords via `map.project()`), then "Copy all" in the `CalibrationFooter` (search → crosshair-focus → drag → copy) to get the plate's JSON to paste back into its `src/data/plates/<slug>.ts` file. The footer's crosshair button, besides centering, makes its pin announce itself — swaps to `pinIconFocused` (warning-yellow dot + looping `animate-ping` halo, `zIndexOffset` above neighbours) for 8s, so the target is findable among dozens of identical dots. **Pin drag must stay Leaflet-NATIVE (`draggable` prop + `dragend`)** — a hand-rolled rewrite cost 6 failed commits: Leaflet markers never fire `pointerdown`/`pointermove` (Leaflet translates pointer events to `mousedown`/`mousemove` before dispatch), and "Shift+drag the pin" can't work either (Shift+drag is Leaflet's BoxZoom gesture at the container level, and `L.Draggable` ignores shift-mousedowns anyway — also no Shift key on iOS). Pin-drop requires **Shift+click** (plain clicks — including both clicks of a double-click-to-zoom — used to litter stray "untitled" pins); that makes adding pins desktop-only, since iOS has no Shift key.
- **Pin hit target:** the visible dot is 24px (`size-6`), but `pinIcon`'s actual `divIcon` is 40px (`iconSize:[40,40]`, dot centered inside via a padded wrapper) with `cursor-grab`/`active:cursor-grabbing` — a slightly imprecise mousedown still grabs the marker instead of falling through to the map's own click handler, which in eyeball mode means "drop a stray new pin", not "drag this one".
- **Positional marker keys + click-reorder = dead popups (fixed 2026-07-17):** pin markers are keyed `` `${term}-${i}` `` and the calibration footer's float-to-top reorders `pins` on marker click — while that reorder ran in VIEW mode too, the clicked marker's key shifted, React remounted it, and Leaflet closes a popup when its marker is removed, so every popup died ~200ms after opening and "View artworks" was unreachable from ALL atlas pins in production (confirmed live via a MutationObserver: popup-added → popup-removed 206ms). `onClickPin` is now passed **only in eyeball mode**. If pin popups ever die-on-open again, suspect any `setPins` (or key-affecting state) in a click path.
- **Known-benign console noise:** ~4× `…/{z}/{row}/-1` tile 404s when a plate opens — Leaflet's `keepBuffer` requests one column past the plate's left edge in the tick before `FitWhenReady`'s `bounds` lands on the `TileLayer` prop. Cosmetic only (fires on the wider plates: rubri/graecia/aegyptus/africae). All in-range tiles exist — every pyramid sampled to its max-zoom corners (originally on Cloudinary 2026-07-17, re-confirmed on R2 2026-08-04 post-migration), incl. the just-past-corner 404 proving config dims match pyramid extents.
- **Pins:** `term` must exactly match the glossary term (or carry `noGloss: true` for deliberate poem-text/label-only pins) or the popup's "View artworks" lookup silently fails (bit us twice: "Mount Olympus" vs glossary "Olympus"; a whole batch-rename in commit `2c4afef`). `label?` supplies a shorter display name without touching the lookup key (e.g. `term: "Argos (the city)"`, `label: "Argos"`, to disambiguate from the dog's entry). **`npm run check:pins`** (`scripts/check-pins.ts`, tsx) guards term validity, plate pixel bounds, per-plate duplicate terms, journey-stop terms, and glossary place coverage (only `Ocean` is deliberately unpinned) — run after every pin or plate change. `PLACES.md` is the regenerated term×plate coverage matrix (source of truth for pin data is each plate file, not the doc).
- **Wheel-zoom sensitivity:** `wheelPxPerZoomLevel` on both `AtlasMap` and `JourneyMap` is `15` (down from a sluggish default `40`) — lower is more sensitive/faster zoom per scroll tick.
- **Place deep links (`#atlas/<slug>/@<term>`):** place cards link into the Atlas focused on that place's pin. `findPin(term, preferSlug?)` in `src/data/plates/index.ts` resolves a term to `{slug, place}` (exact then case-insensitive; an explicit route slug outranks `PLATE_PRIORITY` = graecia → aegyptus → natoliae → palestinae → africae → rubri). `AtlasMap`'s `focusTerm` prop glides to the pin at `maxZoom - 1.5` (tuned by eye — `-2.5` is too wide to read Ortelius's own engraved toponym), reuses the crosshair announce-halo in view mode, and auto-opens the pin's popup via a term-keyed marker-ref registry. **Card click rule:** the 68 places whose art is only a plate crop (every art key ends `-map`) open the Atlas on whole-card click; the 23 with real artwork keep gallery-first click plus a small "Map" button; Ocean (unpinned) is unchanged. Cards are therefore `div role="button"`, not `<button>` — a nested button would be invalid HTML. Popups gate "View artworks" on `hasArt` (real, non-map art), so map-only pins show just the name. The route builder `atlasHash(slug, term)` lives in the plate registry (not `App.tsx`) because the Atlas's own search emits the same links the cards do.
- **In-Atlas place search (view mode only):** `PlateSearch` in `AtlasMap.tsx` — a magnifier button in the modal header that expands to an input; below `sm` the title + plate `<select>` step aside while it's open. It searches **every** plate via `searchPins(q, preferSlug)` over `ALL_PINS` (both in `src/data/plates/index.ts`): substring match on term/label, deduped by term (the open plate wins, else `PLATE_PRIORITY`), prefix matches first and `noGloss` pins last, ≤8 results each labelled with its plate title. Picking one just sets `window.location.hash` to the deep link — same-plate re-fires `DeepLinkFocus` (no remount), cross-plate remounts via `key={slug}`. **Each row's destination goes through `mapRoute()` (see the Journey map section), not `atlasHash` directly**, so the ~9 voyage isles that belong on the Journey map take you there instead of to rubri's cramped inset — and the row's second line prints the *destination's* title ("The Journey of Odysseus"), so the jump is never a surprise. Routing the cards one way and this search the other would be the worst outcome; keep them on the shared policy. Edit mode keeps its separate `CalibrationFooter` pin *filter* (which filters the editable list rather than navigating) and renders no header search. **Gotcha:** the result list is NOT a DaisyUI `menu` — `.menu li > *` uses `grid-flow-col`, which drew the place name and plate name overlapping on one line; and the dropdown needs an explicit `z-[1000]` or the later-positioned map wrapper paints over it.
- **Gotcha — a popup open across a plate switch crashes the app.** `AtlasMap` remounts on `key={slug}`, tearing the popup down mid-flight; Leaflet's `DivOverlay.update()` then runs `_adjustPan` against a removed map (`Cannot read properties of null (reading 'layerPointToContainerPoint')`) and blanks the page. `DeepLinkFocus`'s effect cleanup closes the popup it opened. Rare when popups only opened on click; routine now that every deep link opens one. (Swapping a marker's *icon* is safe — the popup is its own map layer; only unmounting the marker kills it, which is the separate positional-key trap above.)
- **Gotcha — an occluded browser tab suspends `FitWhenReady`.** A backgrounded/hidden tab pauses the render loop, so the `ResizeObserver` never fires, `bounds` stays null, no tiles load and `focusTerm` never resolves — indistinguishable from a broken feature. When driving either map from an automation tool, force a paint (screenshot) between navigations.
- **Entry point / hash routing:** one `parseMapHash` parser in `App.tsx` serves both maps. `#atlas` / `#atlas/<slug>` open a plate (`#journey` / `#journey/<slug>` a journey), a trailing `/@<term>` focuses a pin (split off the RAW hash **before** lowercasing — pin terms are case- and punctuation-bearing — then resolved to the canonical term), and the **universal editing gate is `/edit` appended to any map route** — `#atlas/edit`, `#atlas/<slug>/edit`, `#journey/edit`, `#journey/<slug>/edit`. The pre-`/edit` spellings parse forever as legacy aliases (`#atlas-eyeball`, `#atlas/<slug>-eyeball`, `#journey/<slug>-eyeball`, and journey's original bare `#humaneyeball`); writers (AtlasMap's plate switcher) emit only the `/edit` form. No plate/journey slug may be named `edit`.
- **Pin calibration status (all plates now off their seed grids):** Graecia's 69 pins calibrated 2026-08-07; `rubri` pruned the same day from 100 → **31 pins** (every term Graecia's frame covers was deleted from it — rubri keeps only the Vlyssis-inset mythical/voyage isles, the Underworld rivers, Cyprus, and the Levantine/African/Asian pins) with its Arabia/Persia/India placeholders calibrated onto their printed labels (India is the one compromise — the plate prints no "India", so its pin sits mid-peninsula on "Mambari regnum"); `aegyptus`'s Egypt/Pharos calibrated the same day. The flagged Graecia pins were **reviewed + resolved 2026-08-07** (Argos↔Mycenae swapped onto their own engraved labels, Phylace moved to the Thessalian position, the four interpretive pins confirmed). `africae`'s Africa/Ethiopia/Libya (all 3 pins) were **calibrated 2026-08-07** too, caught mid-Plan.md-Phase-C when their cover-crop bake rendered the plate's title cartouche instead of any real geography — Africa → the plate's own "AFRICAE TABULA NOVA" title text; Libya → "Lybiae Deserta"; Ethiopia (no literal "AETHIOPIA" printed anywhere on this plate) → "totius Africae" in the Prester John legend, the historical European identification of Abyssinia/Ethiopia, the same kind of compromise as rubri's India pin. **Not yet done:** no minimap-size tuning for mobile (fixed 132px width, same as JourneyMap); no drag-declutter pass for dense pin clusters at low zoom.
